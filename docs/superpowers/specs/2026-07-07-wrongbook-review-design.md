# BKYExam 错题复盘增强设计

状态：已实现基础版本。本文保留为设计来源；当前 contract 与完整度以 `docs/api.md` 和 `docs/status.md` 为准。

## 背景

当前 BKYExam 已有错题本基础能力：客观题答错后写入 `wrong_questions`，前端可以按题库筛选、显示错题次数和最近答案，并把条目标记为已掌握。

这个能力足够证明数据链路可用，但还不像真正的订正本。用户真实需要是：看到错题后能重新理解题目、对照自己的错误答案和参考答案、阅读解析、决定是否掌握，并进入再练。

因此错题本下一阶段采用“复盘增强版”，把它从列表页升级为学习闭环入口。

## 目标

- 错题本不只是错误 ID 列表，而是一个可以直接订正的复盘空间。
- 每条错题必须能帮助用户回答三个问题：我错在哪、正确理解是什么、现在要不要再练。
- 宽版页面要像一张有批注区的订正桌面，移动版要像一组可连续翻阅的错题卡。
- 后端 API 要提供复盘需要的真实题目数据，前端不使用假题干、假选项或假解析。

## 非目标

- 不在第一版加入 AI 分析、手写笔记、错因标签体系或复杂统计图。
- 不为主观题自动判分；主观题自评以后用单独设计文档处理。
- 不把错题本做成完整历史练习系统；历史练习记录是后续能力。

## 当前能力

现有 `GET /api/wrong-questions` 返回：

- `id`
- `questionId`
- `bankId`
- `wrongCount`
- `lastAnswer`
- `mastered`
- `lastWrongAt`

现有 `POST /api/wrong-questions/:id/mastered` 可以把错题标记为已掌握。

现有数据表可以通过 `questionId` 和 `bankId` 关联到题目、选项、题库映射和最近作答记录，但当前错题 API 没有把这些数据返回给前端。

## 后端继续设计

### 列表接口增强

`GET /api/wrong-questions` 保留当前筛选参数，并扩展每个条目的复盘展示字段：

```json
{
  "wrongQuestions": [
    {
      "id": "wrong-question-uuid",
      "questionId": "question-uuid",
      "bankId": "bank-uuid",
      "bankName": "C 语言程序设计",
      "subjectCategory": "计算机基础",
      "subjectName": "C 语言",
      "questionType": "single_choice",
      "questionSort": 24,
      "contentPreview": "下列关于数组初始化的说法，正确的是……",
      "wrongCount": 2,
      "lastAnswer": ["B"],
      "mastered": false,
      "lastWrongAt": "2026-01-02T03:04:05.000Z"
    }
  ]
}
```

列表页不需要返回完整解析和完整选项。它只需要足够识别错题、排序、筛选和决定打开哪一题。

### 单题复盘详情接口

新增 `GET /api/wrong-questions/:id`，返回一个错题的完整复盘详情：

```json
{
  "wrongQuestion": {
    "id": "wrong-question-uuid",
    "questionId": "question-uuid",
    "bankId": "bank-uuid",
    "bankName": "C 语言程序设计",
    "subjectCategory": "计算机基础",
    "subjectName": "C 语言",
    "questionType": "single_choice",
    "content": "完整题干",
    "options": [
      { "id": "option-a", "sort": 1, "content": "A. ..." }
    ],
    "lastAnswer": ["B"],
    "correctAnswer": ["A"],
    "analysis": "题目解析原文或清洗后的解析",
    "wrongCount": 2,
    "mastered": false,
    "lastWrongAt": "2026-01-02T03:04:05.000Z"
  }
}
```

详情接口只允许当前登录学生访问自己的错题条目。不存在、不是自己的、或已被过滤策略排除的条目返回 `404`。

### 再练入口

第一版可以采用两阶段：

- 阶段 A：详情页提供“回到对应题库练习”的入口，沿用现有 `POST /api/practice/sessions` 创建题库练习。
- 阶段 B：新增错题再练 session，允许从当前筛选出的错题集合创建一组复盘练习。

阶段 B 采用新增 `POST /api/wrong-questions/review-sessions`。它以当前筛选条件创建错题复盘 session，不改动普通题库练习创建接口的语义。

### 数据和查询边界

- `wrong_questions` 继续保存错题状态、错题次数、最近错误答案和掌握状态。
- 题干、选项、答案、解析来自 `questions` 和 `question_options`，不复制到 `wrong_questions`。
- 题库名、学科、分类来自 `bank_mappings`。
- 最近错误答案优先使用 `wrong_questions.last_answer`，后续如需要完整尝试历史，再查询 `practice_attempts`。
- 列表接口要避免一次返回大量完整题干和解析；详情按需加载。
- 列表页不展示参考答案，避免用户还没进入复盘就直接扫到答案；参考答案只在详情页展示。
- 解析第一版按纯文本展示，保留换行并支持代码块样式容器；不直接渲染未清洗 HTML。

## 宽版体验设计

宽版采用“两栏订正桌面”：左侧是错题队列，右侧是当前错题详情。

左侧队列：

- 顶部显示错题总数、未掌握数量、最近新增时间。
- 提供题库筛选、显示已掌握开关、排序入口。
- 每张卡显示题库名、题型、题号或短 ID、题干摘要、错题次数、最近错误答案和时间。
- 当前选中的错题使用纸张边缘或雾蓝描边标记，而不是强烈高亮。

右侧详情：

- 顶部是题目来源、题型、错题次数和掌握状态。
- 主体展示完整题干和选项，保留练习页已经确认的阅读密度和代码块处理方式。
- 答案区分三层：我的最近错误答案、参考答案、解析。
- 行动区保留“标记掌握”“再练此题/此题库”“下一道错题”。
- 已掌握错题仍可查看，但视觉上降低紧张感，避免误以为还需要处理。

视觉语言：

- 使用雾蓝主题作为默认环境，错题和订正标记使用低饱和陶土色。
- 不使用红色大面积警告；错题本不是惩罚页，而是复盘页。
- 题干区域保持纸质练习册质感，解析区域像老师批注，不像后台日志。

## 移动版体验设计

移动版采用“错题卡连续复盘”：默认展示一题一屏，列表和筛选进入底部抽屉。

常驻层：

- 当前错题题干、选项、我的答案、参考答案和解析。
- 顶部小条显示题库、题型、错题次数和当前位置。
- 底部固定操作：上一题、下一题、标记掌握。

抽屉层：

- 错题列表。
- 题库筛选。
- 显示已掌握开关。
- 再练本组错题入口。

移动端重点不是把宽版全部塞进去，而是保证连续复盘不中断。详情优先，列表退到抽屉。

## 空状态和错误状态

- 没有错题：说明“当前没有需要订正的题”，提供开始练习入口。
- 筛选后为空：提示切换题库或显示已掌握。
- 详情加载失败：保留列表上下文，提示刷新或返回列表。
- 标记掌握失败：不乐观删除条目，显示错误并允许重试。

## 测试要求

后端：

- 列表接口返回增强字段，并仍支持 `bankId` 和 `includeMastered`。
- 详情接口只返回当前学生自己的错题。
- 详情接口能返回题干、选项、参考答案、解析和最近错误答案。
- 非法 UUID、未登录、跨学生访问和不存在条目都有明确响应。

前端：

- 错题列表能渲染增强字段和空状态。
- 详情区能区分我的错误答案、参考答案和解析。
- 标记掌握后列表和详情状态同步。
- 移动端抽屉不阻塞连续复盘。

## 第一版决策

- 错题再练第一版只支持“当前筛选结果”，不做手动多选。
- 参考答案在列表页隐藏，只在详情页展示。
- 解析按纯文本处理，保留换行；如果源数据包含代码片段，前端用代码块容器呈现，不渲染未清洗 HTML。
