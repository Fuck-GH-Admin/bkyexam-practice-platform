# B9.35 Security And Operational Truth Closure

状态日期：**2026-07-16**

## 1. 目标

B9.35 不扩展新的产品页面，而是关闭人工核查中已经确认的安全与运维真相缺口：

1. 临时密码学生不能绕过前端直接调用练习、错题和学习 API。
2. production gate 必须把破坏性 reset gate 纳入 blocking 检查。
3. migration runner 必须记录真实执行历史并检测已发布 SQL 漂移。
4. Admin System Status 必须读取数据库实际 migration 状态，而不是数本地文件。
5. backup/restore drill 必须使用与生产一致的 custom dump，并生成可校验 checksum/evidence。
6. 全量导入维护窗口必须有可重复的 load、iowait、磁盘队列和 API latency 采集工具。
7. Admin Import Jobs 不能默认展示开发机本地路径。
8. 文档必须明确 Learning 当前是后端能力，学生 Web 尚未交付对应页面。

## 2. 已完成改动

### 2.1 首次改密服务端门禁

登录和 session 恢复仍允许返回 `passwordResetRequired=true`，学生也仍可访问改密接口和题库目录；但以下已认证业务命名空间在首次改密完成前统一返回 `403`：

- `/api/practice/*`
- `/api/wrong-questions/*`
- `/api/learning/*`

响应使用共享错误 contract：

```json
{
  "error": "Password change required",
  "code": "PASSWORD_CHANGE_REQUIRED"
}
```

服务端在同一请求中缓存学生 session 解析结果，门禁与后续 route 不会重复查询 session。

### 2.2 Production reset gate

`npm run ops:production-gate` 新增 blocking check：

```text
admin_import_reset_disabled
```

`ADMIN_IMPORT_ENABLE_RESET=true` 时 gate 直接失败。它不再是只靠 runbook 约束的人工检查。

### 2.3 Migration ledger

runner 管理系统表：

```text
schema_migrations
  filename     primary key
  checksum     sha256
  applied_at
```

每次执行 migration 时：

1. 按文件名读取 release 中的 SQL。
2. 计算 SHA-256。
3. 在同一 transaction 中创建并锁定 ledger。
4. 已记录且 checksum 相同的 migration 跳过。
5. 已记录但 checksum 不同则失败，禁止静默修改历史 migration。
6. ledger 中存在但当前 release 缺失的 migration 也失败。
7. 新 migration 执行成功后才写入 ledger。

对尚无 ledger 的旧数据库，第一次运行会重放当前十三份幂等 SQL 并建立历史；第二次运行应全部显示为 skipped。生产执行前必须先备份，并在停写/维护窗口运行。

### 2.4 System Status migration truth

`GET /api/admin/system/status` 的 `database` 摘要现在直接查询 `schema_migrations`：

- `count`：数据库实际记录数。
- `currentMigration`：实际 ledger 中最大的 migration filename。
- ledger 不存在时 `database.ok=false`，不再用仓库文件数量伪装数据库已迁移。

### 2.5 Backup/restore evidence

`npm run ops:backup-restore:docker` 现在：

- 使用 PostgreSQL custom-format dump；
- 写入 `.dump.sha256`；
- 从磁盘重新读取 dump 并校验 SHA-256；
- 使用 `pg_restore` 恢复；
- 比较核心业务表和 `schema_migrations` 计数；
- 写入 `report.json`。

### 2.6 Import maintenance monitor

新增：

```sh
npm run ops:import-maintenance-monitor
```

Linux 维护窗口可按 `before`、`during`、`after` 三阶段采样，报告包括：

- load average；
- CPU user/system/idle/iowait；
- memory/swap；
- block device read/write、utilization、queue depth；
- network rate；
- API process RSS、threads、CPU ticks；
- health/readiness，可选 banks latency；
- 汇总 saturation flags。

它用于证明“导入期间系统是否被磁盘、CPU、内存或 API latency 卡住”，不替代长期外部监控。

### 2.7 Admin import source

Admin Import Jobs 创建表单不再默认填入开发机本地路径。`sourceDir` 现在为空且必填，提示管理员输入服务器 `ADMIN_IMPORT_ALLOWED_ROOTS` 内的真实目录，避免把开发机路径误带到生产请求。

### 2.8 Learning 交付边界

Learning dashboard/trends/goals/review-marks：

- 后端 route、memory/PG repository、shared v1 contract 和测试已完成；
- 当前 `apps/web` 没有 `/learning` 路由、页面或 `/api/learning/*` 调用；
- 因此应表述为“Learning 后端 MVP+”，不能表述为学生端完整功能已交付。
